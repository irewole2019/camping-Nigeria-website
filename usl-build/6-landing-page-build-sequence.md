# Landing Page Build Sequence
## Stage 6 Output | USL Academy

**Product:** Padi Check and the Gate pass
**Date:** 2026-10-17
**Status:** complete
**Stack:** Existing Next.js 16 App Router, React 19, Tailwind v4 (`@theme inline` tokens in `app/globals.css`), local Agrandir and DM Sans fonts. No new UI library.

---

## 1. STRATEGY AND VISUAL THESIS

One big answer per screen. The gate pass sits in the gold box guests already know. Padi Check turns the whole screen into its answer, readable at arm's length at night. Copy is final in `6-landing-page-copy.md`; do not rewrite it.

## 2. TOKENS AND RESPONSIVE RULES

- Brand: `brand-dark #0e3e2e` (Padi Check top bar, login), `brand-accent #e6b325` and `brand-accent-tint #fdf6e3` (gate pass box), `brand-light #f3efe6` (page background).
- Result colours (Padi Check only; full-bleed): green `#15803d`, orange `#c2410c`, red `#b91c1c`, grey `#4b5563`, all with white text. Verify each at WCAG AA for large text and for the detail line.
- Type: result word in `font-serif` (Agrandir) at least 44px on a 360px-wide phone; name at least 24px; buttons at least 56px tall, full width.
- Padi Check is mobile-first and single-column at every width; max content width 480px centred on larger screens.
- QR: at least 220px on the confirmation page, rendered on a white quiet zone inside the gold box; 240px PNG in emails.

## 3. ASSETS BEFORE CONSTRUCTION

- QR images generated by the site (Stage 7 decides the library and route). Emails reference a hosted PNG URL; do not embed base64 or inline SVG in email.
- Gate card: a printable A5 page or PDF using the same three colours and the copy verbatim. The Toyosi number is inserted at print time from the private file, never committed.

## 4. COMPONENTS AND WHY

| Component | Why it exists |
|---|---|
| `GatePass` (QR + code + instruction) | Shared by the confirmation page; the email uses an HTML equivalent |
| `PadiCheckShell` (top bar with count) | Constant context for the volunteer |
| `Scanner` (camera view + Type a code) | Lead capability; typed entry always visible |
| `ResultScreen` (one per state, data-driven) | Same layout, different colour and copy; avoids six bespoke screens |

## 5. IMPLEMENTATION ORDER (presentation)

1. `ResultScreen` with all six states using static fixtures. Review on a real phone outdoors at night before wiring data.
2. `PadiCheckShell` and `Scanner` (typed entry first, camera second).
3. Login screen.
4. `GatePass` on the confirmation page.
5. QR block in the confirmation email and the back-fill email template.
6. Gate card print page.

## 6. PROMPTS (presentation; paste after Stage 8 data sessions or alongside)

**P1, ResultScreen:** "Build a `ResultScreen` component for Padi Check that renders one of six states (welcome, already, not-found, not-paid, offline, camera-off) as a full-viewport colour field using the copy in `usl-build/6-landing-page-copy.md` Surface 5 verbatim. One large result word in font-serif, then the detail lines, then full-width 56px buttons. Each state must be distinguishable without colour (the word carries the meaning). No icons, cards, gradients, animation or sound. Vibrate once via `navigator.vibrate` when available; do nothing where unsupported. Respect reduced motion."

**P2, GatePass:** "Inside the existing gold code box on `app/events/mad-settings/registered/page.tsx`, replace the 'Your code' label and the 'Keep this' line with the Surface 1 copy from `usl-build/6-landing-page-copy.md`, adding the QR above the code on a white quiet zone. Keep the rest of the page unchanged. Do not render a QR when the code fails `isValidSignupCode`."

**P3, Emails:** "Add the Surface 2 QR block to `buildCustomerEmail` and create the Surface 3 back-fill template, each referencing a hosted QR PNG URL, with every user value passed through `escapeHtml`. Match the existing email's inline-style table layout."

**Prohibitions for all prompts:** Do not invent copy. Do not show phone or email on Padi Check. Do not use the words invalid, denied, secure or fraud. Do not use contractions in copy.

## 7. FORMS, ANALYTICS, SEO, LEGAL

- No analytics events on Padi Check beyond what the Scan log records (no guest data to third parties).
- The confirmation page keeps its existing metadata.
